# 📅 Day 63 — Project Scenarios (Asynchronous JavaScript & Error Handling)

The following scenarios are designed to challenge your skills in `fetch`, `async/await`, `Promise.all`, and robust error handling using `try/catch` and custom errors.

---

## ☀️ Scenario 1 — Weather Dashboard with Error Handling

Build a small weather dashboard that fetches current weather data from a public weather API.

> **API Example (OpenWeatherMap):**
>
> `https://api.openweathermap.org/data/2.5/weather?q=${city}&appid=${apikey}`

### 🚀 Key Requirements

* Use `fetch` with **`async/await`** for the API request.
* Implement robust error handling for network/API failures using **`try/catch`**.
* Define and throw **custom errors** (e.g., for extreme temperature) and handle them gracefully.

### 🎯 Suggested Tasks (Focus on UI/UX)

* 🎨 Build a simple UI with an **input field** for the city and a **display area** for the result.
* ⛔ Show **user-friendly error messages** for:
    * Network problems (e.g., computer offline).
    * Invalid city name (API error).
* 🌡️ Demonstrate a **custom error** (e.g., `ExtremeTemperatureError`) when the temperature is above $40^{\circ}\text{C}$ or below $0^{\circ}\text{C}$ (you can use Kelvin to Celsius conversion if needed: $K - 273.15$).

---

## 📧 Scenario 2 — Bulk Email Sending Simulation with Parallel Promises and Error Handling

Simulate sending bulk emails to 5 users. Treat each email-sending operation as a `Promise` with a simulated delay. 

### ⚡ Key Requirements

* Send all 5 "emails" in **parallel** using **`Promise.all`**.
* Catch the error if *any* email fails (simulated failure) and clearly indicate which one failed.
* Use a **`finally`** block to display a completion message, regardless of the overall success or failure.

### ⚙️ Suggested Tasks (Focus on Logic)

* 📝 Create an array of 5 mock email tasks that either **resolve** or **reject** based on a simple random condition (e.g., `Math.random() < 0.8`).
* 🔗 Execute these promises with **`Promise.all`** and handle the results.
* ✅ On success, display a list of all successful emails.
* ❌ On failure, specifically state that the process failed and which email caused the immediate rejection. (Note: Using `Promise.allSettled` is an alternative, but `Promise.all` is required here to practice its fail-fast behavior).
* 🎉 Ensure the **`finally`** message: "Email process is complete." is always the final output.

## 🔗 Optional: Combined Scenario (Advanced)

Combine both scenarios into a small dashboard that:

1.  **Fetches the weather** for a specified city (Scenario 1).
2.  If the weather fetch is successful (and no custom extreme temperature error is thrown), it **attempts to send a "Weather Report" email** to 5 users (Scenario 2).
3.  Demonstrates comprehensive error handling across both the **network operation** and the **simulated async promise operations**.
